# Material limitations

## Authority and semantic coverage
A separately stored manifest can still be wrong. Matching output cannot establish editorial truth, and two incorrect matching inputs can pass. Content keys are supplied, not inferred; translation quality, natural language, ranking, duplicated-content equivalence and search indexing are outside scope. Ambiguity is a non-success result, not a guessed repair.

The default parser implements an explicit static subset on Python events. An optional native Chromium DOMParser adapter independently constructs an inert HTML tree but uses authored selectors and the shared URL normalizer. Neither path executes client JavaScript, Liquid or middleware. Thirty boundary cases and 53 compiled outputs are not full HTML/URI/BCP47 conformance. Noscript remains diagnostic because the deployment's scripting mode is not established. Local HTTP fixtures are not production observations; remote origins and sitemap indexes are never probed. Schema checking rejects unknown policy fields at documented boundaries, not arbitrary extensible observation metadata.

## Population and oracle
Primary cases share one generator. Secondary emitters are separate implementations but mostly authored inputs; public adaptation and Pandoc compilation share one upstream repository. The 96 compositions have been reused and are not an untouched holdout. Tests and labels share the research team's rule design. Chromium adds an independent parser implementation, not an independent human content/policy oracle. No prevalence or field recall can be estimated from injected cases.

## Executed and unexecuted integrations
Pandoc and Chromium ran in the retained experiments. The separate native Hugo adaptation now runs over the same five public source files, but it is not a complete public-site rebuild, native Jekyll, Astro or Next.js execution. The earlier framework source kits remain unbuilt. Hugo evidence covers direct-URL HTML metadata without aliases, sitemaps, themes, Liquid or whole-site body-link auditing. Crawl Cove page functions ran after documented dependency pruning; full CLI, XML/sitemap mode and other maintained tools did not. Scope differences are not scored as shared misses. No historical upstream regression was rebuilt or confirmed by a maintainer; archived-code regressions concern LocaleMesh's own previous code.

## Incrementality and cost
Transactions must contain every relevant primary change. Derived identity buckets are automatic, but missed primary filesystem events are not recovered. Preservation assumes deterministic read-only predicates, complete mediation and normalized complete inputs. The regrouping argument establishes equivalence of the old read relation, not a machine-checked proof of all Python code. Owned inputs protect the supported interface, not deliberate private-attribute mutation.

Coalesced footprints retain exact field observations. Their memory remains data-dependent; unique alias paths limit sharing and can make updates slower than the expanded index. Broad status/policy changes in the retained scale run remain slower than full scans. Membership retention lowers hub-status transaction costs in the subsequent comparison, but the combined path is near parity with an IQR spanning both rankings; global policy still loses by the paired median. Smaller cases include regressions and retained cache memory is unchanged. No adaptive selector was evaluated. Full extraction is not accelerated by the caches. Retained scale timings use isolated processes by change; the maintenance follow-up uses one process and rotated timing blocks. Neither supplies independent sites or multi-machine trials. Memory is live Python allocation including owned input, with available process high-water RSS recorded separately. No universal speedup or threshold follows.

The five-file native Hugo workflow shows no material end-to-end cache benefit after generation, extraction, differencing, export and cold setup. Equal-information batch joins already detect its identity fault. Native timing totals share measured generation/extraction samples across methods and reuse the initial build across cold-start accounts; they are not independently timed deployments. Dependency acquisition, source preparation and publication are excluded. This small public-source adaptation does not estimate production break-even size or closure of the industrial-evidence gap.

The updated membership-retaining engine was timed on reloaded native candidates,
without rerunning generation or extraction. Its checking-only finite costs still
favor batch checking. Those measurements cannot replace the previous native
whole-workflow timings or establish a new generator integration.

## Industry suitability
No organizational release records, deployment duration, operator constraints, integration labor, incidents, triage, waivers, users or commercial outcomes were supplied or measured. The paper remains a laboratory systems study, not an Industry Track field study. Additional synthetic cases, company affiliation, browser execution and public-source reuse cannot replace industrial evidence.
