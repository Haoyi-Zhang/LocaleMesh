# Closest work and bounded contribution

The bibliography and per-key evidence are in `REFERENCE-REVIEW.md`. Documentation fixes the semantic target; it does not establish novelty.

## Multilingual representation and broad constraints
Tonella et al. (ICSM 2002) and Ricca et al. (CSMR 2004) already study multilingual restructuring/alignment and consistent evolution. Web integrity constraints, Despeyroux's semantic analysis, rule-based Web verification, xlinkit and Flexible Consistency Checking already express cross-document relationships. LocaleMesh neither infers translated equivalence nor introduces a new generic rule language. It instantiates explicit published identity and policy for a release candidate.

## Maintained publication checkers
crawlcontract already describes joint sitemap/canonical/redirect/hreflang checks. Therefore no first-joint-checker claim is made. Crawl Cove's page API is now an actual external comparator: fifteen shared stale-target cases are detected by both systems. Six coherent identity swaps are detected only with the separately supplied contract. This distinguishes information provided to the tools, not implementation quality under identical information. Permitted canonicals expose policy disagreement. Optional x-default produces warnings, not errors, and is not counted as an upstream false positive.

## Incremental checking
Egyed (2006), Groher et al. (2010) and Reder/Egyed (2012) already use affected rules and finer rule parts. Pluto, self-adjusting computation, Adapton and other dependency systems supply more general frameworks. The trace-preservation argument is an application of that prior reasoning. Field projections over release facts are not claimed as a new general algorithm.

The measured increment is the application-specific contrast between record topology and actually read fields: changing a hub canonical invalidates one owner, while changing its status invalidates all readers. The tradeoff includes extra comparisons and substantially larger owned caches, and broad changes are slower. Old and absent dependencies and automatic identity-bucket transactions make the implementation's release boundary explicit.

## Contribution that the artifact supports
An executable contract separates content identity and selected publication policy from emitted evidence. The ingestion profile exposes ambiguity instead of silent overwrites. Full checking, three cache representations and a validated transaction API have conditionally explained and extensively tested agreement. A native Pandoc pipeline, an executed external page API, literal parser regressions, scope controls and cost experiments locate specific limits. These are a domain-specific system and bounded empirical findings, not proof of general novelty, industrial impact or universal optimization.

## Low-memory and exact grouping boundary (0.4)
Falleri, Blanc, Bendraou, Almeida da Silva and Teyton, Software: Practice and Experience 44(5), 2014, reduce incremental inconsistency-checking memory with statically generated pre-instantiated impact lists. Their published goal is model-size-independent auxiliary memory, at possible loss of reduction opportunities. CoalescedIncremental instead retains a model-dependent exact dynamic read relation, grouped by equal owner/fact footprints; expanding it recovers the original projected reads. It has no claim to constant space or to being the first memory-efficient consistency checker. The new comparison executes our two exact field representations under identical predicates and updates, not the earlier system. The representation helps repeated fields but loses on distinct alias footprints.

The Chromium experiment adds an independently implemented HTML tree constructor, not an independent policy oracle. The thirteen rejected schema inputs and seven retained parser replays are failures of prior LocaleMesh code, not previously unknown upstream vulnerabilities. These distinctions are part of the substantive contribution boundary, rather than omitted work disguised by a larger mutation count.
